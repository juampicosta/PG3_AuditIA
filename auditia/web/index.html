    ¿Qué requerimientos querés auditar?

    El modelo de lenguaje no decide si un requerimiento está bien o mal: lee el texto y propone las premisas (cuántas obligaciones tiene, qué términos son vagos, si hay un criterio medible, qué falta). Vos las confirmás y recién entonces las reglas del grafo calculan diagnósticos, severidades, prioridades y grados difusos.

    Cómo decide AuditIA

    El sistema separa lo que se sabe de cómo se cuenta. El conocimiento del auditor está guardado en un grafo; el modelo de lenguaje solo traduce entre ese grafo y vos.

    El grafo tiene la última palabra

    Diagnósticos, severidades, prioridades y estados salen de Neo4j: 66 reglas del catálogo y tres modelos difusos. El modelo de lenguaje no puede cambiarlos.

    Requerimientos nuevos con las mismas reglas

    Para un texto nuevo, el modelo de lenguaje solo propone premisas citando el texto; el analista las confirma y las reglas del grafo concluyen. Sin confirmación no se escribe nada.

    Cada experto en lo suyo

    SM1 juzga la calidad de cada requerimiento, SM2 compara requerimientos entre sí y SM3 decide qué tan urgente es tratar cada observación. El prompt maestro elige a quién preguntarle.

    Nada se inventa

    Si el modelo escribe un ID, un número o un estado que no está en la evidencia, el verificador rechaza la respuesta y la vuelve a pedir.

    Todo se puede auditar

    Debajo de cada respuesta están las consultas Cypher, las reglas, la evidencia y la verificación. La traza completa queda guardada en un archivo.
